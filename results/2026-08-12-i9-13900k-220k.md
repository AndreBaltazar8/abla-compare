# 220k single-core result: 2026-08-12

This run verifies the first committed Abla build to sustain the 220,000
requests/second target without removing language features, runtime semantics,
backend support, safety checks, or correctness coverage.

## Configuration

- Intel Core i9-13900K, Linux 6.17.3
- server pinned to quiet P-core CPU 14; its SMT sibling CPU 15 excluded
- `oha` pinned to E-cores 16-31
- HTTP/1.1 keep-alive, 64 connections
- 3-second warm-up followed by five 10-second samples per server
- release builds from committed trees
- every server validated for status, exact 14-byte body, and content type before
  timing

## Result

| Server | Samples (requests/second) | Median | p50 | p99 |
| --- | --- | ---: | ---: | ---: |
| Abla | 220,889; 212,030; 220,714; 221,769; 220,215 | **220,714** | 0.257 ms | 0.520 ms |
| Go | 156,408; 164,323; 156,599; 164,617; 164,014 | 164,014 | 0.389 ms | 0.810 ms |
| Rust | 282,259; 281,826; 282,373; 281,484; 281,923 | 281,923 | 0.230 ms | 0.243 ms |

Abla delivered 134.6% of Go's throughput and 78.3% of Rust's. It improved
25.5% over the 175,820 requests/second typed-collection baseline and 35.8% over
the 162,515 requests/second compact-value baseline.

## What changed

All specialized operations retain their generic dynamic fallbacks, and all
indexed operations retain checked bounds and type behavior. The gains came
from eliminating redundant work on already-proven typed paths:

| Optimization checkpoint | Median requests/second |
| --- | ---: |
| Typed collections | 175,820 |
| Typed string equality and direct interpolation conversion | 184,437 |
| Checked statically known object-field indexes | 190,284 |
| Direct response write from the request region | 199,398 |
| Native scalar SSA through typed length and index operations | 207,755 |
| Native array/string equality and field scalar propagation | 214,822 |
| Eliminate a duplicate post-write monotonic-clock read | **220,714** |

The direct-write path resets request memory only after a completed write. On
backpressure, it still promotes the unwritten response tail and unread input
tail before either can outlive the request region. The timestamp removal also
preserves idle-timeout semantics: successful reads already record activity,
while queued/backpressured writes still update it when they make progress.

Several plausible changes were benchmarked and rejected because they regressed
or did not materially improve the result, including a larger GC threshold,
region-aware GC triggering, uninitialized network buffers, inline allocation
initialization, scalar object-field stores, flattened template concatenation,
and status-reason fast paths. They are not present in the final tree.

## Instruction-level check

A separate 10-second `perf stat` run of the exact final Abla binary delivered
220,270 requests/second (approximately 2,204,804 requests):

| Counter | Total | Per request |
| --- | ---: | ---: |
| Instructions | 54,777,071,005 | 24,844 |
| Cycles | 24,000,639,609 | 10,886 |
| Branches | 9,304,648,037 | 4,220 |
| Branch misses | 3,580,620 | 1.624 |

The run sustained 2.28 instructions per cycle with a 0.04% branch-miss rate.
Compared with the typed-collection checkpoint, it used 39.3% fewer
instructions and 33.6% fewer cycles per request. The stripped server binary was
337,520 bytes.

## Integrity verification

The final compiler/runtime tree passed `make -j2 check`: 75 passed, 0 failed,
and 0 skipped. This includes both LLVM and C backend coverage, native network
and WebSocket tests, and a byte-identical optimized self-rebuild whose native
child also passed. The benchmark harness separately verified every endpoint
before each timed series.

Abla reaches **68.1% of Go throughput** and **39.9% of Rust throughput** in

109,657 req/s result, the native scalar ABI improves throughput by **1.25%**.

## Compiler change

The typed IR now retains function parameter and result types. Direct calls to
functions with explicit `int` or `bool` types pass scalar parameters and return
scalar results in LLVM registers. Generated boxed wrappers preserve the public
and indirect-call ABI for closures, exports, reflection, default arguments,
and dynamic dispatch.

The optimization is conservative where storage and semantic types differ:
inferred results remain boxed, and ordinary lambda captures remain boxed
because they are passed as cell objects. Function fingerprints include the
new ABI types so incremental reuse cannot link incompatible direct functions.

An interleaved five-pair A/B run on the same CPU measured a 107,812 req/s
baseline and 110,210 req/s candidate median, a **2.22%** improvement. The
candidate won all five pairs and every request succeeded. This tighter test
isolates the compiler change; the full three-server table above is the
canonical cross-language rerun.

## Verification

The compiler passed all 74 manifest tests, including the new scalar ABI case,
return control, default arguments, indirect callable families, closure cell
captures, networking, WebSocket, and libc-free fixtures. The C-backend
differential checks passed, LLVM verification passed, and the pure-Abla O2
self-rebuild produced byte-identical compiler IR and a working native child.

This is a verified step toward lowering boxed hot-path work, but it does not
close the remaining gap by itself. Function bodies still materialize many
`AblaValue` slots and box scalar intermediates. The next compiler experiment
should promote proven scalar locals and temporaries into SSA values while
retaining boxed values only at escaping, dynamic, and compatibility
boundaries.

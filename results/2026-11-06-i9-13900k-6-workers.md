# HTTP comparison — November 6, 2026 — six P-core workers

Abla uses the frozen stage-2 compiler of `f6aeaebb8bd36248af5ccea063a8263be0d46431`, SHA-256 `835b1b227f0fbfe205c68f569a0bd283ac8b29806d5ad793ba16678a29952ee1`. This is the approved master snapshot, before the later v0.2.47 changes. Release builds; no Abla, Rust or Zig source changes. The Go streaming-echo correctness fix is `2e61a35d57cd0acaccc0687bb016f8076f18d1b8`.

All four servers were built using the README’s pinned Nix shell. Toolchains: Go 1.26.7, Rust 1.95.0, Zig 0.16.0, oha 1.16.0; Linux 6.17.3. The full hashes and locked package revisions are in the JSON provenance. In particular, Abla uses the project lock’s `abla-web` c1da1a31, without updating dependencies.

Intel Core i9-13900K: CPU 12/13 are offline, leaving seven physical P-cores; the configuration was observed and preserved. Servers use P-cores 0,2,4,6,8,10: six individually pinned Abla processes, Go GOMAXPROCS=6, Rust Tokio workers=6, and Zig two event workers with two handler threads each (six active workers). Clients use E-cores 16–31 and 256 connections.

Each cell is the median of three ten-second samples, after three seconds of warmup. Samples, latency distributions, statuses and errors remain in raw JSON. The same deterministic response oracle is checked twice on one persistent connection before timing. Body-echo response byte counts are additionally checked in the timed samples. No feature was disabled to improve a result.

The scheduled quiet window held both NovaKind full-test slots and both build slots through fair-flock, with ablac agents pausing heavy jobs. Residual desktop/background load was retained, as agreed: one-minute load min/median/max 4.15/14.86/20.03. One-second observations and per-repetition load ranges are attached to the results; this is a shared-machine measurement, not an isolated laboratory.

The preflight regression fails with the old Go binary and passes with EnableFullDuplex; all four servers pass 128/1024/16384/65536-byte persistent echoes (32 exact responses), and all 84 scenario/server preflights pass (168 responses).

Abla has the highest median in 20 of 21 six-worker scenarios. Plaintext reaches 1,717,173 req/s versus Go 670,135, Rust 1,257,729 and Zig 1,336,398. JSON strings remain the sole median deficit: Abla 518,477 versus Rust 627,092 req/s (17.3% behind). Headers and parameters, behind at one worker, are respectively 8.2% and 32.6% ahead of the best peer here. The JSON scan profile in the one-worker report is consistent with the persistent strings gap; it is not a six-worker profile or a proof of the exact scaling mechanism. A comparison of different connection counts and client CPU sets is not a parallel-efficiency measurement.

The workload/API differences already present in the harness are retained: parameters-16 uses positional path/query access in Abla and Zig, named access in Go, and mixed access in Rust. JSON cases use a fixed compact field order; Abla uses its canonical-order streaming reader/encoder, while peers use typed schema decoders/serializers. These results describe those programs, not all JSON or routing APIs. The raw configuration records these differences.

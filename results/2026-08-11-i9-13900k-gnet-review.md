# Gnet-informed single-worker result: 2026-08-11

Machine: Intel Core i9-13900K, Linux 6.17.3, one pinned server CPU, separate
client CPUs. The load was HTTP/1.1 keep-alive with 64 connections, a 3-second
warm-up, and three 10-second measurements. Values below are medians. The
harness validated HTTP 200, the content type, and the exact response body
before load, and every measured request succeeded.

| Server | Requests/second | p50 latency | p99 latency |
| --- | ---: | ---: | ---: |
| Abla Web + event HTTP | 109,657 | 0.443 ms | 0.869 ms |
| Go `net/http` | 163,238 | 0.392 ms | 0.823 ms |
| Rust Axum/Tokio | 278,429 | 0.231 ms | 0.247 ms |

Toolchains: Abla compiler commit `dab2dc3`, Abla Web commit `b56bc8c`, Go
1.25.1, Rust 1.95.0, Axum 0.8.9, Tokio 1.53.1, and oha 1.10.0. The raw samples
and complete machine/configuration metadata are in the adjacent JSON result.

Abla reaches **67.2% of Go throughput** and **39.4% of Rust throughput** in
this practical routed-HTTP comparison. Against the immediate 103,875 req/s
checkpoint, the combined event-interest and lazy-routing changes improve
throughput by **5.57%**.

## Changes retained

The event server no longer issues `epoll_ctl(MOD)` after every ordinary
response. Read interest stays registered, while writable interest is enabled
only when a nonblocking write becomes partial and removed after that backlog
drains. A five-second syscall audit with 64 persistent connections observed
132 `epoll_ctl` calls, and a forced 256 KiB response with a 4 KiB server send
buffer verifies the real backpressure path.

Abla Web now allocates path-match storage only for parameterized routes and
context-state storage only when middleware writes state. An interleaved
five-pair A/B run measured 109,196 req/s against 105,653 req/s for the previous
router, a **3.35%** improvement under the same binaries and CPU placement.

## Experiments rejected

- Writing queued strings through a new offset API measured 106,292 req/s,
  about 1% below its checkpoint, so it was removed.
- Correct edge-triggered epoll improved p99 from about 0.876 to 0.548 ms, but
  reduced throughput to 105,331 req/s and worsened p50; it was not made the
  throughput-oriented default.
- Reusing a native epoll event buffer through ordinary boxed buffer access
  measured 97,615 req/s. The allocation disappeared, but repeated managed
  field and byte-load work cost more than the compact intrinsic, so the entire
  prototype was removed.

These results support the architectural lesson without treating `epoll` as a
magic switch: Abla already had direct epoll, descriptor-indexed connection
state, `SO_REUSEPORT` workers, and immediate nonblocking writes. The retained
gain came from reducing steady-state control syscalls and managed allocations.
Breaking 200k on one core now requires lowering the boxed request/response
instruction count, not another readiness flag.

## Verification

The compiler/runtime suite passed all 73 fixtures, including advanced network
and forced HTTP backpressure tests, followed by a byte-identical pure-Abla O2
self-rebuild. Abla Web's framework, generated-source, and database/message-bus
integration suites also passed. The final comparison completed all nine timed
samples with a 100% request success rate.

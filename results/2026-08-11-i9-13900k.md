# Optimized managed HTTP result: 2026-08-11

Machine: Intel Core i9-13900K, Linux 6.17.3, one pinned server CPU, separate
client CPUs. The load was HTTP/1.1 keep-alive with 64 connections, a 3-second
warm-up, and three 10-second measurements. Values below are medians. The
harness validated HTTP 200, the content type, and the exact response body
before load, and every measured request succeeded.

| Server | Requests/second | p50 latency | p99 latency |
| --- | ---: | ---: | ---: |
| Abla Web + event HTTP | 86,786 | 0.484 ms | 0.971 ms |
| Go `net/http` | 163,076 | 0.391 ms | 0.821 ms |
| Rust Axum/Tokio | 281,494 | 0.229 ms | 0.244 ms |

Toolchains: Abla compiler commit `ca90be2`, Abla Web commit `12e44b0`, Go
1.25.1, Rust 1.95.0, Axum 0.8.9, Tokio 1.53.1, and oha 1.10.0.

## Change from the broken baseline

The same managed Abla server previously sustained 4.7 requests/second with
12.9-second median latency. It now serves **about 8,800 times as many requests
per second** in the first fixed baseline and **about 18,500 times as many** in
the final result. The final result is also **2.09 times** the preceding 41,511
requests/second baseline. This is not a collector-disabled shortcut: the
service still selects managed collection through
`memorySetLimit(memoryLimit())`.

The dominant defect was a real leak. A socket read allocated a 65,537-byte
native buffer whose integer address required it to begin pinned. Turning that
buffer into a managed string transferred ownership but did not change the
allocation's pinned layout, so the collector could never reclaim any adopted
read buffer. The runtime now publishes the managed layout at adoption and has
a regression that requires an abandoned adopted buffer to be collected.

The remaining gains came from bounded native text scans, collector-safe string
views, one parse per framed request, exact-size compact reads, direct
descriptor-to-slot lookup, packed poll-event consumption, allocation-free
static-route dispatch, leaner response framing, and an immediate small-write
attempt that preserves the existing partial-write/backpressure path.

The second pass applies whole-program LTO to hosted O2 executables while
retaining the normal 3.0 MiB relocatable sidecar for Icy packaging. Managed
arrays and compiler-known object fields keep their initial storage inline;
constructors initialize those sized slots without repeated field searches. The
collector replaces allocation sorting with an exact-pointer hash index, and
string views explicitly retain their byte owner. A cache-hit build reproduced
the same 563 KiB optimized executable byte-for-byte.

## Instruction-level comparison

`perf stat` measured each pinned server during a separate ten-second run:

| Counter per request | Abla | Rust | Abla/Rust |
| --- | ---: | ---: | ---: |
| Retired instructions | 84,115 | 14,017 | 6.00x |
| CPU cycles | 43,425 | 5,427 | 8.00x |
| Branches | 14,044 | 2,348 | 5.98x |
| Branch misses | 0.110% | 0.082% | 1.34x |
| Instructions/cycle | 1.94 | 2.58 | 0.75x |

Abla's hottest symbol was managed memory pressure at 24.4% of sampled cycles;
allocator consolidation and allocation were the next substantial shared costs.
Rust's hottest named symbols were Hyper request parsing and response writing.
The throughput gap is therefore primarily excess managed-value construction,
heap traffic, and lower locality, rather than different benchmark work or a
single socket flag. Kernel syscall tracepoints were not readable by this user,
so no syscall-count claim is included.

## Sustained memory check

The final Abla binary ran for 120 seconds under the same 64-connection load. It
completed **11,148,227 successful HTTP 200 responses** at 92,900
requests/second with p99 0.953 ms. The process remained alive, every request
succeeded, and peak RSS was 135,080 KiB.

Correctness gates also passed: all 73 compiler/runtime conformance fixtures,
the byte-identical pure-Abla self-rebuild, all Abla Web tests, hosted HTTP
tests, and a statically linked raw-target server serving the expected response.

## Remaining gap

Abla now reaches about 53% of Go's throughput and 31% of Rust's in this test.
The next general compiler/runtime work is typed-value unboxing and escape
analysis, stack or request-region placement for non-escaping graphs, and a
generational collector with write barriers. Those changes can preserve dynamic
values, reflection, managed lifetimes, mutation, backpressure, and the C/raw
backends; disabling safety or special-casing a constant response would only
invalidate the comparison.
